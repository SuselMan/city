# Загрузка и кеш игры

Сервер предпросмотра отдаёт файлы с Cache-Control: no-store. Поэтому обычный HTTP-кеш спрайтов не ускорял обновление страницы. Изменения общего сервера для этого не требуются.

boot.js регистрирует sw.js только в каталоге этой игры и ждёт контроль страницы максимум 1,2 секунды; затем последовательно загружает Phaser, симуляцию и игру. При недоступном service worker игра запускается обычным способом. Постоянная ссылка предпросмотра использует отдельные ссылки на boot.js и sw.js рядом с index.html, game.js и sim.js.

Service worker кеширует только WebP в assets и Phaser. Первый запрос получает файл с сервера и сохраняет ответ в Cache API; повторные запросы получают локальную копию. Cache API хранит ответы явно, в том числе когда обычный HTTP-кеш запрещён no-store. HTML, boot.js, game.js, sim.js, CSS и сохранения в этот кеш не входят. Ключ включает scope игры; старые версии только её кеша удаляются при активации нового. Отказ хранилища не мешает загрузке графики.

При изменении содержимого существующего файла графики нужно дать ему новое имя либо увеличить версию CACHE в sw.js. Оригинальные PNG сохранены. scripts/encode-assets.cjs создаёт WebP без потерь и проверяет все значения альфа и RGB каждого видимого пикселя. RGB полностью прозрачных пикселей может быть нормализован кодеком, что не влияет на вид или hit-testing. 18 используемых изображений: 18,80 МБ PNG → 10,81 МБ WebP. Старый неиспользуемый supply-atlas не загружается.

Прогресс загрузки показан процентами. qa/terrain-topology-browser-check.cjs проверяет первоначальную загрузку, обновление, активный service worker и отсутствие передачи WebP по сети на повторной загрузке. Эти времена зависят от VPS и сети; на устройстве пользователя могут отличаться. Тестовый браузер и его профиль закрываются после проверки.
